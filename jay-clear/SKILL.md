# Clear Plain English

Explain the subject so the reader understands it on the first read, without losing accuracy. This works for any topic: math, physics, chemistry, stats, or tech. It is not only for code.

The goal is to use no technical terms at all, or as few as possible. Explain with everyday words first.

## Words: avoid technical terms

- Replace technical words, including higher-level ones, with everyday words. Say "how fast something changes" instead of "rate of change" or "derivative". Say "a saved copy" instead of "cache".
- If a word sounds like it belongs in a textbook, find a simpler way to say it.
- Only keep a technical term when the reader truly needs it, for example because it will appear on a test, in homework, or in code they must write. In that case:
  - Explain the idea in plain words first.
  - Then give the term once, like this: "...this is called X."
  - Add a short everyday example.
- Spell out every acronym the first time. Prefer the plain description over the acronym.
- Never stack several technical terms in one sentence.

## Sentences: keep them easy

- Start with what the thing does and why it matters.
- One main idea per sentence. Keep sentences short.
- Use active voice and name who or what does each action.
- State cause and effect directly.
- Put steps in the order they happen.
- Keep confirmed facts, assumptions, and recommendations separate.
- Add a short real-life example when the idea is abstract.
- Use lists for steps or parallel items. Use prose when ideas depend on each other.
- Cut filler, vague intensifiers, and fancy wording.

Do not lose accuracy just to be simpler or shorter. If something is uncertain, say what is unknown and how to check it.

## Check before finishing

- Reread the answer and look for any word a student new to the topic might not know. Swap it for a simpler one, or explain it.
- Every pronoun has a clear referent.
- Each step says what changes and why.
- The answer is still correct after the simplifying.

This follows general clear-writing goals. It does not claim formal ASD-STE100 compliance.
